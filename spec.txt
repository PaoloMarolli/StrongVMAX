StrongVMAX — Specifica Completa per Webapp
Contesto e obiettivo
StrongVMAX è una webapp per il tracking degli allenamenti in palestra, ispirata all'app Strong (iOS). È una
PWA (Progressive Web App) installabile su iPhone come app nativa, ottimizzata per uso mobile. Gli utenti
sono un gruppo ristretto (uso personale + amici/colleghi), con login tramite Google. La lingua
dell'interfaccia è l'italiano.
Stack tecnologico consigliato
 Framework: Next.js 14+ (App Router)
 Styling: Tailwind CSS
 Database: Supabase (PostgreSQL hosted, gratuito fino a 500MB)
 Autenticazione: Supabase Auth con provider Google
 Deploy: Vercel (gratuito)
 PWA: next-pwa per installazione su iPhone
Supabase è necessario per avere dati persistenti e sincronizzati tra utenti diversi. I dati NON vanno nel
localStorage — ogni utente ha i propri dati sul database.
Autenticazione
 Login esclusivamente tramite Google OAuth
 Ogni utente vede solo i propri dati (template, sessioni, esercizi)
 Nessuna registrazione manuale — basta il Google Account
 Sessione persistente (non viene chiesto di fare login ogni volta)
Struttura dell'app — Navigazione
L'app ha una bottom tab bar con tre voci:
[ Routine ]   [ Storico ]   [ Esercizi ]
Schermata 1 — Routine (tab principale)
Lista template
 Mostra tutti i template dell'utente come card
 Ogni card mostra: nome template, tutti gli esercizi del template (lista completa, non troncata),
numero totale esercizi
 Due bottoni per card: Modifica e Inizia
 Bottone + in alto a destra per creare nuovo template
 Bottone ■ Workout libero in alto a sinistra per allenamento senza template
 Riordinamento template tramite drag & drop
 Eliminazione template con swipe
 Nessun limite al numero di template (uso personale)
Creazione/modifica template

Sheet modale con:
 Campo nome template
 Lista esercizi aggiunti (riordinabili, eliminabili)
 Per ogni esercizio, pannello configurazione espandibile: numero serie (stepper), numero reps
(stepper), peso default (kg), riposo automatico (30s, 45s, 60s, 90s, 120s, 150s, 180s, 240s, 300s)
 Bottone per aggiungere esercizi dal catalogo
Schermata 2 — Allenamento attivo (ActiveWorkout)
Si apre come fullscreen quando si preme "Inizia" su un template o "Workout libero".
Palette colori — tutta l'app
I colori da usare in tutta l'interfaccia sono esclusivamente:
 Blu (#0057FF o simile) — azioni primarie, bottoni principali, valori chiave
 Azzurro (#00AAFF o simile) — timer, accenti secondari, link
 Nero (#000000 / #111111) — sfondi dark, testo primario in dark mode
 Bianco (#FFFFFF / #F5F5F5) — sfondi light, testo in dark mode
Nessun arancione, verde, viola o rosso nell'interfaccia. I badge W/D/F e la variazione % usano sfumature di
blu/azzurro e bianco/grigio. Eccezione: il bottone "Fine" può essere blu scuro o nero.
Header fisso
 Timer workout (formato HH:MM:SS, colore azzurro) — parte in automatico
 Volume totale in kg (somma di tutti i set completati, colore blu)
Card per ogni esercizio
Intestazione card:
 Nome esercizio (tappabile → apre sheet dettaglio esercizio)
 Volume esercizio in kg (solo set completati, esclusi warmup)
 Badge variazione % rispetto alla settimana precedente
Rest timer bar:
 Appare automaticamente dopo il tick su una serie completata
 Mostra: label "riposo", countdown MM:SS, barra di progresso, bottone "salta"
 Il tempo di riposo è personalizzabile per ogni esercizio
Tabella serie — colonne: # | prec. | kg | reps | ✓
 Colonna #: bottone con menu — Normale, W (Warmup, escluso dal volume), D (Dropset), F
(Cedimento/Failure)
 Colonna prec.: peso×reps della stessa serie nella sessione precedente (es. "80kg×8")
 Colonna kg: campo numerico editabile
 Colonna reps: campo numerico editabile
 Colonna ✓: checkbox — quando spuntata parte il rest timer automaticamente
Calcolo volume:
 Volume = kg × reps per ogni serie completata
 I set Warmup sono ESCLUSI dal volume
 I set Failure contano normalmente

Bottoni toolbar:
 Annulla (grigio, sx) → alert di conferma → elimina sessione senza salvare
 Fine (blu scuro, dx) → alert con riepilogo (durata + volume) → salva e chiude
Workout libero: parte da schermata vuota, empty state con bottone "Aggiungi esercizio", salvato nello
storico come "Workout libero".
Schermata 3 — Storico (tab)
Lista sessioni
 Sessioni raggruppate per settimana (es. "Questa settimana", "Settimana scorsa", "14 Apr – 20 Apr")
 Ogni card mostra: nome template, data, durata, volume totale, numero esercizi
 Tap sulla card → apre dettaglio sessione
Dettaglio sessione
Header con 5 stat: durata, volume totale, numero esercizi, PR 1RM, PR Volume.
 PR 1RM: numero di esercizi in cui l'1RM teorico del topset supera il massimo storico
 PR Volume: numero di esercizi in cui il volume totale supera il massimo storico
 Le righe con PR mostrano un badge "PR" in blu
 Tabella esercizi con colonne: #, Tipo, kg, reps, 1RM teorico
 Badge tipo set (W/D/F) visibili
 Highlight del topset (stella + riga evidenziata)
 1RM teorico con formula Epley: peso × (1 + reps/30)
Schermata 4 — Esercizi (tab)
 Lista esercizi raggruppati per gruppo muscolare
 Barra di ricerca per nome o gruppo muscolare
 Bottone + per aggiungere esercizio custom
 Esercizi custom: modificabili e eliminabili (swipe), badge visivo
Catalogo predefinito
 Petto: Panca piana, Panca inclinata, Croci cavi
 Spalle: Shoulder press, Alzate laterali
 Schiena: Trazioni, Rematore bilanciere, Lat machine
 Gambe: Squat, Leg press, Romanian deadlift
 Bicipiti: Curl bilanciere
 Tricipiti: Tricep pushdown
 Core: Plank
Sheet — Dettaglio esercizio
Si apre tappando il nome di un esercizio durante il workout.
 Stat card "1RM teorico best" — il massimo 1RM teorico raggiunto in assoluto (colore blu)
 Stat card "Sessioni totali" — numero di sessioni in cui è stato eseguito

 Grafico lineare — andamento 1RM teorico nel tempo (asse X: date, asse Y: kg), un punto per
sessione, curva interpolata
 Storico sessioni — lista inversa con: data, topset (peso×reps), 1RM teorico
Calcolo topset: la serie completata (non warmup) con l'1RM teorico più alto in quella sessione.
Formula 1RM (Epley):
1RM = peso × (1 + reps / 30)
Se reps = 1 → 1RM = peso
Modello dati — Schema database (Supabase/PostgreSQL)
Tabella exercises
id           uuid PRIMARY KEY
user_id      uuid REFERENCES auth.users  -- null = predefinito globale
name         text NOT NULL
muscle_group text
equipment    text
is_custom    boolean DEFAULT false
created_at   timestamp DEFAULT now()
Tabella workout_templates
id         uuid PRIMARY KEY
user_id    uuid REFERENCES auth.users NOT NULL
name       text NOT NULL
order      integer DEFAULT 0
created_at timestamp DEFAULT now()
Tabella template_exercises
id                   uuid PRIMARY KEY
template_id          uuid REFERENCES workout_templates ON DELETE CASCADE
exercise_id          uuid REFERENCES exercises
exercise_name        text
default_sets         integer DEFAULT 3
default_reps         integer DEFAULT 8
default_weight       numeric DEFAULT 0
default_rest_seconds integer DEFAULT 90
order                integer DEFAULT 0
Tabella workout_sessions
id               uuid PRIMARY KEY
user_id          uuid REFERENCES auth.users NOT NULL
template_id      uuid  -- null per workout libero
template_name    text
date             timestamp DEFAULT now()
duration_seconds integer DEFAULT 0
Tabella exercise_logs
id           uuid PRIMARY KEY
session_id   uuid REFERENCES workout_sessions ON DELETE CASCADE
exercise_id  uuid REFERENCES exercises
exercise_name text
rest_seconds  integer DEFAULT 90
order         integer DEFAULT 0
Tabella workout_sets
id               uuid PRIMARY KEY
exercise_log_id  uuid REFERENCES exercise_logs ON DELETE CASCADE
weight           numeric DEFAULT 0
reps             integer DEFAULT 0
set_type         text DEFAULT 'normal'  -- normal|warmup|dropset|failure
is_completed     boolean DEFAULT false
order            integer DEFAULT 0
Logica business — Regole importanti

Volume
volume_set     = weight × reps  (se is_completed = true E set_type ≠ 'warmup')
volume_exercise = somma volume_set
volume_session  = somma volume_exercise
Variazione % settimanale
delta = ((volume_attuale - volume_settimana_scorsa) / volume_settimana_scorsa) × 100
Confronto: stesso esercizio, stessa settimana precedente, per user_id
Colonna "prec."
Per ogni set in posizione N, mostrare peso×reps del set in posizione N della sessione precedente più
recente che conteneva lo stesso esercizio.
PR (Personal Record)
 PR 1RM: 1RM teorico topset sessione attuale > massimo storico per quell'esercizio
 PR Volume: volume totale esercizio sessione attuale > massimo storico per quell'esercizio
 Il conteggio PR nell'header = numero di esercizi che hanno battuto almeno un record
Rest timer
 Parte automaticamente quando un set viene spuntato
 Countdown da rest_seconds a 0
 Bottone "salta" per interrompere
 Personalizzabile per esercizio (non per singolo set)
PWA — Requisiti
 Installabile su iPhone tramite Safari → "Aggiungi a schermata Home"
 Icona app personalizzata e splash screen
 Funzionamento offline per i dati già caricati (service worker)
 Layout ottimizzato per viewport mobile (375px–430px)
 Nessuna bottom bar del browser visibile quando installata
UX — Note di design
 Dark mode supportata (segue le impostazioni di sistema)
 Font system (San Francisco su iOS)
 Bottom tab bar fissa
 Le card degli esercizi durante il workout devono essere scrollabili verticalmente
 I campi kg e reps hanno tastiera numerica
 Il timer workout NON si ferma se si cambia tab
 Feedback aptico sui tick (se supportato dal browser)
Note per lo sviluppatore
1. Supabase: configuralo prima di tutto — crea il progetto su supabase.com, esegui le migration SQL,
configura Google OAuth nelle impostazioni Auth.
2. Next.js App Router: usa Server Components dove possibile, Client Components solo per
interattività (timer, form).

3. Timer workout: va gestito con un context globale per non perdersi al cambio di tab.
4. Sessione in corso: salvata in modo incrementale (ogni set completato → upsert su Supabase) per
evitare perdita dati se l'utente chiude il browser.
5. Vercel deploy: collega il repo GitHub a Vercel, aggiungi le env variables
NEXT_PUBLIC_SUPABASE_URL e NEXT_PUBLIC_SUPABASE_ANON_KEY.
6. PWA: configura next-pwa con manifest.json e service worker per caching offline.
